01 / Executive summary

One narrow job, done at the edge.

The KWS engine is not a general speech recognizer. It decides whether a custom keyword has occurred, using a compact classifier and a local trigger gate.

01
◉

Privacy by architecture

Microphone audio stays on the device during idle listening. The design target is 0% idle-audio minutes transmitted.

LOCAL FIRST
⌁

Efficient edge inference

Custom INT8 model, fixed-size features, static/preallocated memory where practical, and temporal smoothing.

TINYML
⇢

Cloud only on activation

After a valid trigger, preserve configurable pre-roll and stream only the command audio to a remote ASR gateway.

TRIGGER GATED
Hard boundary: RAM below 256 KB and idle CPU below 10% are project acceptance gates. The ESP32-S3 reference hardware has more physical SRAM than this application budget; available memory must not be confused with the allowed application working RAM.

Functional requirements

  1. Capture mono audio at 16 kHz, 16-bit PCM or equivalent low-overhead format.
  2. Maintain a small ring buffer for configurable pre-roll.
  3. Extract MFCC or log-Mel features locally.
  4. Run an INT8 custom classifier with keyword, silence and unknown classes.
  5. Use temporal smoothing / consecutive-hit logic to reduce false activations.
  6. On trigger, preserve pre-roll, continue capture and begin secure streaming.
  7. Do not upload idle audio; transmit only what the command protocol needs.
  8. Measure keyword-end to ASR-receive latency using synchronized timestamps.
  9. Expose RAM, model size, feature/inference time, CPU, trigger counts and latency percentiles.
  10. Allow model replacement without rewriting the application layer.

Explicit non-goals

  • Full speech recognition on the microcontroller.
  • Large transformer or uncompressed neural network inference on the edge.
  • Using global assistant keywords such as “Alexa” or “Hey Google”.
  • Always-on cloud upload of microphone audio.
  • Claiming production accuracy before controlled hardware testing.
Reporting rule: do not present target values as achieved results. Replace “target” with “measured” only when reproducible raw logs exist.
03 / System architecture

The cloud stays out of the idle loop.

A deterministic edge signal-processing and classifier pipeline hands off to a separately upgradeable server and ASR adapter only after activation.

Detailed runtime flow

STEP 01Boot & validateCheck model checksum; initialize microphone and memory arena.
STEP 02Warm upFill audio ring buffer and compute fixed-size feature frames.
STEP 03Listen locallyRun KWS inference and update temporal state continuously.
STEP 04Trigger & streamFreeze pre-roll; attach device/session ID and timestamp; send command audio.
STEP 05ASR & closeReceive transcript/events; close on endpoint silence or timeout.

State machine

01

IDLE

Local audio analysis only. No audio upload.

02

DETECTED

Threshold + consecutive windows pass.

03

STREAMING

Pre-roll + command frames sent securely.

04

ASR → COMPLETE

Transcript/action returned; stream closed.

Telemetry should store non-audio metrics by default: trigger time, latency, model version and error code.

Dataset design

  • Positive: many speakers, ages, accents, volumes and distances saying the custom keyword.
  • Hard negatives: phonetically similar phrases, partial keywords, background speech and common commands.
  • Unknown: varied speech that is not the keyword.
  • Silence / noise: fan, traffic, keyboard, machinery, TV, music and room responses.
  • Speaker-disjoint split: keep speakers separated across train, validation and test to prevent leakage.
  • Locked test set: never use it for threshold tuning.
  • Track provenance and licenses for every external audio file.
Speech Commands = reference, not a substitute for custom-keyword data

Engineering rules

MUST USE
  • Open-source KWS pipeline and custom keyword.
  • INT8 or demonstrably compact model.
  • Static memory where practical.
  • Speaker-disjoint dataset splits.
  • Hardware measurements and versioned logs.
  • Model checksums, training config, SBOM/license audit.
  • All commercial figures in ₹.
MUST AVOID
  • Proprietary activation SDKs prohibited by the brief.
  • Global assistant wake words.
  • Large/uncompressed edge models.
  • Continuous raw audio cloud upload.
  • Speaker leakage and accuracy-only reporting.
  • Invented prototype results or unsupported savings claims.
  • Paid dependencies where suitable open alternatives exist.

User feedback protocol

  • Pilot with 10–20 users, each doing 30–50 intentional keyword trials in quiet and noisy conditions.
  • Rate perceived activation delay on a 1–5 scale; record false-trigger reports.
  • Test at 0.5 m, 1 m, 2 m and 3 m where hardware permits.
  • Use at least three representative noise environments and multiple speakers.
  • Mine hard negatives, retrain, and freeze the test set before final benchmark.

Core formulas

TPR / Recall = true detections ÷ true keyword attempts

FAR = false triggers ÷ hours of negative listening

Precision = true detections ÷ all detections

Latency & cost

Latency = first ASR-received byte timestamp − keyword-end timestamp

ASR cost/month = activated audio minutes × vendor ₹/minute

Impact metrics

Privacy: idle audio minutes transmitted target 0% · Speed: P50/P95 · Efficiency: RAM + idle CPU · Reliability: FAR per 8/24 h · Maintainability: successful OTA updates / total.

RAM and idle CPU are first-class acceptance gates, not late optimizations.
